## **Objective**
To create a background worker that asynchronously analyzes a user's recent assessment history to identify strengths, weaknesses, and learning patterns. This moves heavy analytical processing off the synchronous API request path, ensuring the `/api/v1/assessment/analysis` endpoint remains fast and responsive.

## **Success Criteria**
- [x] A new `WeaknessAnalysisService` is created to contain the analysis logic.
- [x] The service fetches recent assessment data for a user from the `AssessmentRepository`.
- [x] The service performs aggregations to identify patterns (e.g., most common incorrect categories).
- [x] The service uses an AI call (via `PromptTemplateEngine`) to generate a qualitative summary and recommendations.
- [x] The final analysis report is saved to the `user_weakness_analyses` table.
- [x] A mechanism to trigger this worker is established (e.g., a job queue or a scheduled task).
