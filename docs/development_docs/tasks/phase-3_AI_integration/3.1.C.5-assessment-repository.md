## **Implementation Details**

### **1. Repository Class Structure**

The repository will be a simple class that takes a `Knex` instance in its constructor. This allows it to be used with the main database connection or with a transaction-specific connection.

```typescript
// server/src/repositories/assessmentRepository.ts

import { Knex } from 'knex';
import { GradingResult, WeaknessAnalysis } from '../types/Assessment';

export class AssessmentRepository {
  constructor(private db: Knex) {}

  /**
   * Returns a new repository instance with the provided transaction object.
   * This is key for ensuring all operations within a service method run
   * on the same transaction.
   */
  withTransaction(trx: Knex.Transaction): AssessmentRepository {
    return new AssessmentRepository(trx);
  }

  // ... methods
}
```

### **2. `saveGradingResult` Method**

This method is responsible for persisting the outcome of a graded exercise. It needs to perform multiple inserts that are linked together.

```typescript
// server/src/repositories/assessmentRepository.ts (inside the class)

async saveGradingResult(
  userId: number,
  exerciseId: string, // Assuming exerciseId is a string, e.g., from ai_generated_content
  result: GradingResult
): Promise<void> {
  // 1. Create the main completion record for the exercise
  const [completion] = await this.db('user_content_completions')
    .insert({
      userId,
      contentId: exerciseId, // This assumes exerciseId maps to content.id
      score: result.overallScore,
      completedAt: result.completedAt,
      // attemptNumber would need to be calculated or passed in
    })
    .returning('*');

  if (!completion) {
    throw new Error('Failed to create content completion record.');
  }

  // 2. Prepare the detailed assessment records for each question
  const assessmentRecords = result.individualGrades.map(grade => ({
    userId,
    userContentCompletionId: completion.id,
    assessmentType: grade.assessmentType,
    userResponse: grade.metadata?.userResponse, // Assuming response is in metadata
    isCorrect: grade.isCorrect,
    score: grade.score,
    feedback: JSON.stringify(grade.feedback), // Ensure feedback is stringified for JSONB
    confidence: grade.confidence,
    metadata: JSON.stringify(grade.metadata || {}),
  }));

  // 3. Batch insert all assessment records
  if (assessmentRecords.length > 0) {
    await this.db('user_assessments').insert(assessmentRecords);
  }

  // TODO: Add logic to update the user_progress summary table.
  // This might involve incrementing lessonsCompleted, updating accuracyRate, etc.
  // This logic could also be handled by the asynchronous worker (Task 3.1.C.7).
}
```

### **3. `getLatestWeaknessAnalysis` Method**

This method will perform a simple query to get the most recent analysis report for a user.

```typescript
// server/src/repositories/assessmentRepository.ts (inside the class)

async getLatestWeaknessAnalysis(userId: number): Promise<WeaknessAnalysis | null> {
  const analysis = await this.db('user_weakness_analyses')
    .where({ userId })
    .orderBy('analyzedAt', 'desc')
    .first();

  return analysis || null;
}
```

## **Review Points & Solutions**

-   **🔍 Review Point: Separation of Concerns**
    -   **Concern**: The business logic for grading should not be mixed with SQL queries.
    -   **Solution**: This repository class is the solution. It cleanly separates the "how" of database interaction (SQL queries via Knex) from the "what" of the business logic (calculating scores, generating feedback), which resides in the `AIAssessmentEngine`.
-   **🔍 Review Point: Transaction Handling**
    -   **Concern**: How does the repository participate in a transaction started by the service?
    -   **Solution**: The `withTransaction` method is the key. The service layer starts a transaction and creates a *new* repository instance that is bound to that transaction. All subsequent calls on that instance (`assessmentRepoTrx.saveGradingResult(...)`) will execute within the transaction, guaranteeing atomicity.
-   **🔍 Review Point: Performance**
    -   **Concern**: Inserting assessment records one by one would be slow.
    -   **Solution**: The `saveGradingResult` method uses a batch `insert` for all `user_assessments` records. This is significantly more performant than inserting each record in a loop, as it requires only a single round trip to the database.
